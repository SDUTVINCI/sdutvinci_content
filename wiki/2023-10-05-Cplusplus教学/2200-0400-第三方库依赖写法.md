本节专门讲第三方库如何安装、如何在 CMake 中查找、如何放到模板的 `Third-party dependencies` 区块里。

本模板的原则是：

```cmake
# ========================
# Third-party dependencies
# ========================
find_package(Eigen3 REQUIRED)

target_link_libraries(${PREFIX}_src_lib
  PUBLIC
    Eigen3::Eigen
)
```

也就是：

1. 谁使用第三方库，谁写 `find_package`。
2. 第三方依赖集中放在本模块的 `Third-party dependencies` 区块。
3. 优先链接现代 CMake target，例如 `Eigen3::Eigen`、`OpenCV::opencv_core`。
4. 不把所有第三方库都堆到顶层 `CMakeLists.txt`。

安装命令按系统选择：Linux 使用系统包管理器，Windows 本教程使用 MSYS2 UCRT64。`pacman` 命令在 UCRT64 终端执行，日常 CMake 命令可以在配置好 PATH 的 PowerShell 中执行。安装同一个库后，两种平台尽量复用下面的 target 写法。

## `find_package` 基本语法

```cmake
find_package(<PackageName> [version] [REQUIRED] [COMPONENTS components...])
```

常见写法：

```cmake
find_package(Eigen3 REQUIRED)
find_package(OpenCV REQUIRED)
find_package(Boost REQUIRED COMPONENTS system filesystem)
find_package(PCL REQUIRED COMPONENTS common io)
```

参数说明：

| 参数 | 作用 |
|:---|:---|
| `<PackageName>` | 包名，例如 `Eigen3`、`OpenCV` |
| `version` | 要求的最低版本或精确版本 |
| `REQUIRED` | 找不到就直接报错 |
| `COMPONENTS` | 只查找某些组件 |

### `REQUIRED`

```cmake
find_package(Eigen3 REQUIRED)
```

如果没找到 Eigen，CMake configure 阶段直接失败。

如果不写：

```cmake
find_package(Eigen3)
```

则需要自己判断：

```cmake
if(Eigen3_FOUND)
  target_link_libraries(my_target PUBLIC Eigen3::Eigen)
endif()
```

工程模板里通常写 `REQUIRED`，因为依赖缺失时越早报错越好。

### `COMPONENTS`

OpenCV、Boost、PCL 这类库通常有多个模块。

例如：

```cmake
find_package(OpenCV REQUIRED COMPONENTS core imgproc highgui)
```

表示只需要：

1. `opencv_core`
2. `opencv_imgproc`
3. `opencv_highgui`

这样比直接引入全部 OpenCV 更清楚。

## `target_link_libraries` 里的依赖可见性

第三方库链接时也要考虑 `PUBLIC`、`PRIVATE`、`INTERFACE`。

| 关键字 | 什么时候用 |
|:---|:---|
| `PRIVATE` | 第三方库只在 `.cpp` 里使用，头文件不暴露它 |
| `PUBLIC` | 头文件里包含了第三方库类型，使用者也需要知道它 |
| `INTERFACE` | 当前 target 自己不编译，只向下游传递 |

例如，`lib1` 的头文件如果只是这样：

```cpp
#pragma once

namespace lib1 {
void run_eigen_vector_example();
}
```

头文件没有暴露 Eigen 类型，那么 Eigen 可以用 `PRIVATE`：

```cmake
target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    Eigen3::Eigen
)
```

如果头文件写成：

```cpp
#pragma once

#include <Eigen/Dense>

namespace lib1 {
Eigen::Vector3d make_vector();
}
```

此时下游包含这个头文件时也需要 Eigen include 路径，所以应该用 `PUBLIC`：

```cmake
target_link_libraries(${PREFIX}_src_lib
  PUBLIC
    Eigen3::Eigen
)
```

本模板示例用 `PUBLIC`，是为了展示依赖传播；实际项目中可以按头文件是否暴露第三方类型来选择。

## Eigen3

Eigen 是常用线性代数库，主要是头文件库。

### 安装

Ubuntu/Debian：

```bash
sudo apt install libeigen3-dev
```

Fedora：

```bash
sudo dnf install eigen3-devel
```

Windows，MSYS2 UCRT64：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-eigen3
```

软件包信息见 [MSYS2 官方包页面](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-eigen3)。

Eigen 是头文件库，重点是让 CMake 找到头文件和 `Eigen3Config.cmake`。自行安装时，设置安装前缀 `CMAKE_PREFIX_PATH`，或把 `Eigen3_DIR` 指向配置文件目录；不需要为 GCC 和 MSVC 分别编译一份 Eigen。

### CMake 写法

```cmake
# ========================
# Third-party dependencies
# ========================
find_package(Eigen3 REQUIRED)

target_link_libraries(${PREFIX}_src_lib
  PUBLIC
    Eigen3::Eigen
)
```

### C++ 使用

```cpp
#include <Eigen/Dense>

Eigen::Vector3d v(1.0, 2.0, 3.0);
```

### 可见性建议

| 场景 | 链接方式 |
|:---|:---|
| Eigen 只在 `.cpp` 中使用 | `PRIVATE Eigen3::Eigen` |
| 头文件暴露 `Eigen::Matrix`、`Eigen::Vector` | `PUBLIC Eigen3::Eigen` |

## OpenCV4

OpenCV 是计算机视觉库，模块很多，建议按组件引入。

### 安装

Ubuntu/Debian：

```bash
sudo apt install libopencv-dev
```

Fedora：

```bash
sudo dnf install opencv-devel
```

### 常用组件

| 组件 | 作用 |
|:---|:---|
| `core` | 基础数据结构，例如 `cv::Mat` |
| `imgproc` | 图像处理 |
| `imgcodecs` | 读写图片 |
| `highgui` | 简单窗口显示 |
| `videoio` | 摄像头和视频读写 |
| `calib3d` | 相机标定、几何 |
| `features2d` | 特征点 |
| `dnn` | DNN 推理模块 |

Windows，MSYS2 UCRT64：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-opencv
```

软件包信息见 [MSYS2 官方包页面](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-opencv)。

MSYS2 软件包随仓库更新，不保证一直提供同一个 OpenCV 主版本。本节的 API 示例沿用 OpenCV 4 的用法；如果项目明确要求 4.x，应安装相应版本并检查 CMake 的版本要求。还要确认下载的 Windows 二进制库是否适合当前 MinGW 工具链，不能直接假定其他编译器生成的库可混用。

### CMake 写法：推荐按组件

```cmake
# ========================
# Third-party dependencies
# ========================
find_package(OpenCV REQUIRED COMPONENTS core imgproc imgcodecs highgui)

target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    opencv_core
    opencv_imgproc
    opencv_imgcodecs
    opencv_highgui
)
```

有些 OpenCV 安装会提供 `OpenCV::opencv_core` 这种 imported target，也可以写：

```cmake
target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    OpenCV::opencv_core
    OpenCV::opencv_imgproc
    OpenCV::opencv_imgcodecs
    OpenCV::opencv_highgui
)
```

如果你的系统没有这些 `OpenCV::` target，就使用前一种 `opencv_core` 写法。

### CMake 写法：简单粗暴版

```cmake
find_package(OpenCV REQUIRED)

target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    ${OpenCV_LIBS}
)
```

这种写法能用，但不如组件写法清楚。模板教学推荐优先按组件写。

### C++ 使用

```cpp
#include <opencv2/opencv.hpp>

cv::Mat image = cv::imread("test.png");
```

## PCL

PCL 是点云库，机器人、三维感知、SLAM 项目中常用。

### 安装

Ubuntu/Debian：

```bash
sudo apt install libpcl-dev
```

Fedora：

```bash
sudo dnf install pcl-devel
```

### 常用组件

| 组件 | 作用 |
|:---|:---|
| `common` | 点类型、基础工具 |
| `io` | PCD/PLY 等文件读写 |
| `filters` | 滤波 |
| `features` | 特征 |
| `registration` | 配准 |
| `segmentation` | 分割 |
| `visualization` | 可视化 |

Windows：

PCL 的依赖较多，先确认是否有适合当前 MinGW-w64 / UCRT64 工具链的安装方式。可以在 UCRT64 中搜索：

```bash
pacman -Ss pcl
```

按搜索结果确认仓库、架构和实际包名，再决定是否安装；没有合适的包时，需要用匹配的工具链构建 PCL 及相关依赖。不要把某个 MSVC 预编译安装包直接当成 MinGW 库使用。源码构建的基本要求见 [PCL 官方 Windows 构建说明](https://pointclouds.org/documentation/tutorials/compiling_pcl_windows.html)，其中的编译器示例也要结合当前工具链判断。

### CMake 写法

```cmake
# ========================
# Third-party dependencies
# ========================
find_package(PCL REQUIRED COMPONENTS common io filters)

target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    ${PCL_LIBRARIES}
)

target_include_directories(${PREFIX}_src_lib
  PRIVATE
    ${PCL_INCLUDE_DIRS}
)

target_compile_definitions(${PREFIX}_src_lib
  PRIVATE
    ${PCL_DEFINITIONS}
)
```

有些 PCL 版本也提供 imported targets。如果你的环境支持，可以优先使用类似：

```cmake
target_link_libraries(${PREFIX}_src_lib
  PRIVATE
    PCL::common
    PCL::io
    PCL::filters
)
```

实际选择以你本机 `find_package(PCL ...)` 提供的结果为准。

例如 `lib1` 同时使用 Eigen 和 OpenCV：

```cmake
target_link_libraries(${PREFIX}_src_lib

    opencv_imgcodecs

```

## 不推荐的写法

### 不推荐：顶层集中查找所有库

```cmake
# 顶层 CMakeLists.txt
find_package(Eigen3 REQUIRED)
find_package(OpenCV REQUIRED)
find_package(PCL REQUIRED)
```

问题：

1. 顶层越来越乱。
2. 不知道哪个模块真正用了哪个库。
3. 删除模块时容易漏删依赖。
4. 新人阅读工程时依赖关系不清楚。

### 不推荐：全局 include

```cmake
include_directories(${OpenCV_INCLUDE_DIRS})
link_libraries(${OpenCV_LIBS})
```

问题：

1. 影响所有 target。
2. 依赖关系不明确。
3. 可能引入意外的 include 顺序问题。

现代 CMake 推荐：

```cmake
target_link_libraries(my_target
  PRIVATE
    opencv_core
)
```

如果库提供 imported target，include 路径和链接库会自动跟着 target 传播。

## 排查 `find_package` 找不到库

### 第一步：确认系统包是否安装

```bash
dpkg -l | grep eigen
rpm -qa | grep eigen
```

### 第二步：确认 CMake 能看到 config 文件

常见文件名：

```text
Eigen3Config.cmake
OpenCVConfig.cmake
PCLConfig.cmake
fmtConfig.cmake
```

### 第三步：手动指定搜索路径

如果库安装在非标准目录，可以在 configure 时添加：

```bash
cmake --preset linux-debug -DCMAKE_PREFIX_PATH=/opt/some_library
```

或在 preset 中添加：

```json
"CMAKE_PREFIX_PATH": "/opt/some_library"
```

多个路径可以用分号：

```json
"CMAKE_PREFIX_PATH": "/opt/lib_a;/opt/lib_b"
```

### 第四步：查看 CMake 报错信息

CMake 通常会告诉你缺少哪个 config 文件，例如：

```text
Could not find a package configuration file provided by "OpenCV"
```

这种情况优先检查：

1. 开发包是否安装。
2. 包名是否正确。
3. 是否安装到了非标准路径。


## Windows 的查找路径和运行环境

已经安装库但 CMake 仍然找不到时，可以在 PowerShell 中指定安装前缀：

```powershell
$env:CMAKE_PREFIX_PATH = "C:/deps/eigen;C:/deps/opencv"
cmake --preset windows-debug
```

这里填安装根目录，多个 Windows 前缀用分号分隔。也可以使用本地 `CMakeUserPresets.json` 保存这些路径。项目包配置仍应优先提供可复用的 imported target。

`find_package` 成功后，还要实际运行程序。开发时可以把依赖的 `bin/` 加入 PATH；验证安装结果时，按所用第三方库的安装要求准备运行环境。

模板只处理自己的目标和常用 GCC 运行库。添加新的第三方依赖后，还要补齐相应安装步骤，并检查安装后的程序能否运行。
