通过 ”**一、Boost库介绍安装\+串口通信基础实现**“ 的内容，可以完成串口通信基础的收发功能。

**但也发现一个明显问题：**

**在第一部分的实现，做到了先发送一组数据给PC机，然后程序一直挂起，持续等待串口通信另一方发送信息，并将接收到的信息打印输出到终端中。**

**也就是说串口通信的接收方一直处于堵塞程序运行的状态，一直在等待串口通信的另一方，向本机发送信息并将信息打印输出。程序只能执行接收功能，无法执行其他功能，而且一旦进入接收函数，也无法给另一方发送信息，显然不符合工程需要。**

为了解决这个问题，我们引入C\+\+多线程标准库 `<thread>`，将串口通信的接收方，单独放入一个线程，使接收方在程序一开始执行时，就开始执行接收功能（在程序执行周期内不间断，也可以防止信息获取遗漏），达到不干扰主线程功能运行的目的。

”**二、上下位机串口通信协议**“ 的内容介绍了串口通信打包的流程

使用通信协议好处：

- **错误检测和校验：** 通信协议通常包括错误检测机制，如 CRC 校验、奇偶校验、求和校验等，可以确保数据在传输过程中未被篡改或损坏。

- **标准化数据格式：** 通过使用协议，数据格式是标准化的，发送方和接收方都能够按照协议解析数据，确保数据的解码和理解一致。

/*
需要发送变长的数据帧

帧头：使用 0xA5,0x5A两个字节作为帧头
帧长：根据数据帧实际长度确定帧长字节，这里只使用1个字节
命令字节：利用命令字节指定数据字节的功能
数据字节：数据字节长度可变，帧长字节为0  表示没有数据，帧长字节为255，表示有255字节数据
校验字节：在MODBUS协议中常用CRC16循环冗余校验方式   将校验字节前的所以字节加入计算，得到两字节CRC16校验码，本文采用此方式
帧尾：这里使用0xFF作为帧尾。

帧头                数据长度        命令                数据                CRC16校验        帧尾
A5 5A                XX         XX                …XX                 …XX XX                 FF
2字节                1字节            1字节                n字节 …                 2字节                1字节
*/

// 16位循环冗余校验  不需要改动
uint16_t SerialPort::CRC16_Check(const uint8_t* data, uint8_t len)
{
        uint16_t CRC16 = 0xFFFF;
        uint8_t state, i, j;
        for (i = 0; i < len; i++)
        {
                CRC16 ^= data[i];
                for (j = 0; j < 8; j++)
                {
                        state = CRC16 & 0x01;
                        CRC16 >>= 1;
                        if (state)
                        {
                                CRC16 ^= 0xA001;
                        }
                }
        }
        return CRC16;
}

// 发送数据包   不需要改动
void SerialPort::Send_Cmd_Data(uint8_t cmd, const uint8_t* datas, uint8_t len)
{
        uint8_t buf[300], i, cnt = 0;
        uint16_t crc16;
        buf[cnt++] = 0xA5;
        buf[cnt++] = 0x5A;
        buf[cnt++] = len;
        buf[cnt++] = cmd;
        for (i = 0; i < len; i++)
        {
                buf[cnt++] = datas[i];
        }
        crc16 = CRC16_Check(buf, len + 4);
        buf[cnt++] = crc16 >> 8;
        buf[cnt++] = crc16 & 0xFF;
        buf[cnt++] = 0xFF;
        Send(buf, cnt); // 调用数据帧发送函数将打包好的数据帧发送出去
}

// 接收数据   不需要改动
void SerialPort::Receive(uint8_t bytedata)
{

        static uint8_t step = 0; // 状态变量初始化为0 在函数中必须为静态变量
        static uint8_t cnt = 0, Buf[300], len, cmd, * data_ptr;
        static uint16_t   crc16;
        // 进行数据解析 状态机
        switch (step)
        {
        case 0: // 接收帧头1状态
                if (bytedata == 0xA5)
                {
                        step++;
                        cnt = 0;
                        Buf[cnt++] = bytedata;
                }
                break;
        case 1: // 接收帧头2状态
                if (bytedata == 0x5A)
                {
                        step++;
                        Buf[cnt++] = bytedata;
                }
                else if (bytedata == 0xA5)
                {
                        step = 1;
                }
                else
                {
                        step = 0;
                }
                break;
        case 2: // 接收数据长度字节状态
                step++;
                Buf[cnt++] = bytedata;
                len = bytedata;
                break;
        case 3: // 接收命令字节状态
                step++;
                Buf[cnt++] = bytedata;
                cmd = bytedata;
                data_ptr = &Buf[cnt]; // 记录数据指针首地址
                if (len == 0)
                        step++; // 数据字节长度为0则跳过数据接收状态
                break;
        case 4: // 接收len字节数据状态
                Buf[cnt++] = bytedata;
                if (data_ptr + len == &Buf[cnt]) // 利用指针地址偏移判断是否接收完len位数据
                {
                        step++;
                }
                break;
        case 5: // 接收crc16校验高8位字节
                step++;
                crc16 = bytedata;
                break;
        case 6: // 接收crc16校验低8位字节
                crc16 <<= 8;
                crc16 += bytedata;
                if (crc16 == CRC16_Check(Buf, cnt)) // 校验正确进入下一状态
                {
                        step++;
                }
                else if (bytedata == 0xA5)
                {
                        step = 1;
                }
                else
                {
                        step = 0;
                }
                break;
        case 7:                              // 接收帧尾
                if (bytedata == 0xFF) // 帧尾接收正确
                {
                        Data_Analysis(cmd, data_ptr, len); // 数据解析
                        step = 0;
                }
                else if (bytedata == 0xA5)
                {
                        step = 1;
                }
                else
                {
                        step = 0;
                }
                break;
        default:
                step = 0;
                break; // 多余状态 正常情况下不可能出现
        }
}

上述代码将通信协议部分函数全部变为SerialPort类内公有函数，成为该类的实现方法，故在每个SerialPort对象创建时，这些方法即为该对象的固有实现方法，不需要再使用对象调用 ”发送一个字节的函数“ 放入SendByte\(\)函数中。



## 【多线程调用部分】

- thread\_main\.cpp

```C++
#include"serialport.h"
#include<thread>
#include <chrono>
using namespace std;

void Serial_Receive(SerialPort& port) {
    port.runService();
}

int main()
{
    SerialPort port;
    uint8_t datas[] = { 0x11,0x15 };
    port.init("COM1", 115200);

    std::thread serialport_receive(Serial_Receive, ref(port));
    while (true) {
        port.Send_Cmd_Data(0, datas, 2);
        std::this_thread::sleep_for(std::chrono::milliseconds(1000));  // 延时 1000 毫秒 (1 秒)
    }

    serialport_receive.join();

    return 0;
}
```

【多线程实现方式】

- 后者专门用于串口通信的监听方实现，保证串口通信监听方做到实时堵塞第二个线程，实时监听串口通信另一方向本机发来的信息，保证了信息监听不会出现遗漏，也保证了数据的完整性。

- 主线程中可以放入程序的主逻辑功能，其中串口通信的发送也在主线程中完成，主线程中程序可以在任意时间利用串口`SerialPort`对象调用`Send_Cmd_Data()`函数向串口通信另一方发送消息。值得注意的是，该函数的底层发送函数`wirte()`本身就是异步函数，他不会阻塞主线程，他的发送也不占用主线程时间，因此把串口通信的发送放在主线程中，并不会导致主线程程序运行变慢。
