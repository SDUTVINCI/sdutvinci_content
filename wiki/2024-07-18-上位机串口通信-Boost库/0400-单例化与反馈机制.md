本节是在前面几节的基础上做的一个延申，主要包括两个部分：**单例化** 和 **串口通信的反馈机制**。

- 首先来说一下单例化：

单例化本身是C\+\+类实现的一种操作，又称单例模式。顾名思义就是指在整个系统[生命周期](https://so.csdn.net/so/search?q=%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F&spm=1001.2101.3001.7020)内，保证一个类只能产生一个实例，确保该类的唯一性。（严格的说，是在任意时刻只能一个地方在使用该对象）

使用它的两个原因：

1. 节省资源。一个类只有一个实例，不存在多份实例，节省资源。

2. 方便控制。在一些操作公共资源的场景时，避免了多个对象引起的复杂操作。

至于今年串口通信使用单例化的原因，很大一部分是因为今年工控机和主控板的串口通信只使用了一个串口，因此使用单例化节省了开销也可以保证串口使用的安全。

【注意】在实现单例模式时，需要考虑到线程安全的问题。

- 其次说一下反馈机制：

使用反馈机制一开始是由控制提出的，主要是为了保证串口通信的安全和过程的完整，后续在和一些学长和其他学校的交流中了解到，这个机制可能并不必要，但是在机器人运行测试时上下位机程序纠错中可能能起到一定作用，往后的队员在使用过程中看需求决定是否使用吧。

具体包括两个过程，这里只提供上位机部分：

1. 上位机连续向下位机发送某个固定信息，直到下位机给与反馈（指定信息回复），上位机停止发送。

（对于下位机就是，接收到上位机信息后给与反馈，如果上位机还在发送，就继续反馈，直到上位        机不再发送）

2. 上位机收到下位机发送的信息，并给与下位机反馈（指定信息回复），下位机停止发送，如果下位机还在发送，就继续给下位机反馈，直到下位机不再发送。

\(对于下位机就是，向上位机连续发送某个固定信息，直到接收到上位机反馈，下位机停止发              送）

### 单例化使用

1. `getInstance` 方法：

```C++
static SerialPort& getInstance() {
    static SerialPort instance; // 静态局部变量
    return instance;
}
```

- `getInstance` 方法返回 `SerialPort` 类的唯一实例。

- 静态局部变量 `instance` 保证了 `SerialPort` 类在整个程序生命周期内只有一个实例。首次调用时，`instance` 被创建，后续调用直接返回该实例。



2. 私有构造函数和析构函数：

```C++
SerialPort();
~SerialPort();
```

- 将构造函数和析构函数设为私有，确保类的实例只能通过 `getInstance` 方法访问，外部不能直接创建或销毁该类的实例。

### 【注意】

**在使用单例化的时候一定要注意，要保证程序在运行的整个时间线上，任意一个时刻或一段时间（一个流程周期）要保证只能有一个地方调用此单例化对象。**

如果出现一个时刻程序多线程的多个位置要使用串口通信对象，则可能出现程序的多个位置争用对象的情况。虽然程序使用互斥锁以及线程间提醒机制，不会导致程序崩溃，但争对象的行为可能导致，线程程序堵塞、信息丢失的可能，程序执行效率低下。

一般情况下，我们所写的代码虽然有面向对象的特征，但实际上嵌入机器人的程序是一个面向过程的程序，只要保证程序是一个流程进行的（包换循环流程），一般都不会导致上述情况。



同时，建议在往后的过程中，上下位机的串口通信使用两个或两个以上的串口，在信息交流上有显著的优点，在与其他高校的交流过程中，大部分高校串口都是采用的两个及以上串口，两个串口一般是足够的。

```C++
void SerialPort::ReceiveFeedback_mechanism(mutex& data0xXX_mutex,
                                            condition_variable& data0xXX_cond,
                                            uint8_t* data0xXX,
                                            bool& isReceived,
                                            bool& data_ready,
                                            uint8_t cmd,
                                            bool is_reset_data)
{
    while (true)
    {
        {
            std::unique_lock<std::mutex> lock(data0xXX_mutex);
            if (!isReceived)
            {

                data0xXX_cond.wait(lock, [&data_ready,&is_reset_data]
                    {return ((!is_reset_data&&MCU_Reset!=-1)||data_ready); });
                if(!is_reset_data&&MCU_Reset!=-1){
                    data0x00_data_ready = false;//---------------------------------------注意这个地方
                    cout<<"程序复位"<<endl;
                    break;
                }

                this->Send_Cmd_Data(cmd, data0xXX, 1);
                isReceived = true;
            }
            else
            {
                if (!data0xXX_cond.wait_for(lock, std::chrono::milliseconds(50), [&data_ready] { return data_ready; })){
                    data_ready = false;
                    isReceived = false;
                    break;
                }
                else
                    this->Send_Cmd_Data(cmd, data0xXX, 1);
            }
            data_ready = false;
            data0xXX_cond.notify_one();
        }
    }
}
```



#### 运行流程

**接收反馈的流程**：当函数开始运行之后，便开始等待指定信息（根据cmd帧和len帧来判断指定信息），函数会锁                            定第一次接收到对应信息，并给下位机反馈，使用多线程`wait_for()`函数在指定时间之内如                            果接收到下位机再次发来信息，就再次给下位机反馈，并再次判断指定时间内是否接收到指定                            信息；如果指定时间内未接收到指定信息，则判断为下位机没有再发送信息，函数退出。

【**注意**】：`wait_for()`函数内要填写延时时间ms单位，这个函数的作用是如果在指定时间内如果满足了要求的条件就不阻塞线程（满足条件立刻跳出，不会等完延时时间）如果不满足条件，超过延时时间之后，就不再阻塞程序。

1. **设置的延时时间一定要大于下位机的发送延时，否则会出现失效⭐**

- serialport\.cpp功能部分

```C++
void SerialPort::SendFeedback_mechanism(mutex& data0xXX_mutex,
    condition_variable& data0xXX_cond,
    uint8_t* data0xXX,
    bool& isReceived,
    bool& data_ready,
    uint8_t cmd,
    uint8_t len)
{
    while (true) {
        std::unique_lock<std::mutex> lock(data0xXX_mutex);
        data0xXX_cond.wait(lock, [&isReceived]
            { return !isReceived; });
        if (!data_ready) {
            this->Send_Cmd_Data(cmd, data0xXX, len);
            // 可以考虑加入一定的延时
            std::this_thread::sleep_for(std::chrono::milliseconds(15));
        }
        else {
            data_ready = false;
            isReceived = false;
            break;
        }
        data0xXX_cond.notify_one();
    }
}
```



#### 运行流程

**发送反馈的流程：**当函数开始运行之后，程序会先对指定信息的相关变量上锁（根据cmd帧和len帧来判断指定信                            息），然后对是否接收到下位机信息的标志位作为wait\(\)函数的判断条件，如果没有接收到下位                          机信息就继续执行，向下位机发送指定信息，如果下位机给与反馈，第二个标志位就会在另一                            个线程被赋值，从而在下一个函数内循环中因为这个标志位的改变得知下位机给与反馈，然后                            退出函数，解锁并通知其他线程；否则就会继续执行下一次的程序内循环。

【**注意**】

1. **向下位机的发送一定要设置延时，并且最好要大于5ms，上位机cpu主频远远大于单片机，如果不加延时连续给下位机发送信息，会直接把下位机干爆⭐  **

## 序言

串口通信的全部程序见顶部压缩包，一\~四部分是对本年上位机工程串口通信部分代码的讲解：

**对于串口通信部分的改进和优化意见：**

1. **串口通信的硬件部分，建议上下位机使用两个串口**（多线程代码，在并行部分，可能导致需要同时发送两种以上不同信息）这时单个串口就不够用；

    两个串口也可以设置优先级，比如下位机复位后发送的第一条信息，就可以作为上位机得知下位机复位的条件，这种重要的信息，就可以放在优先级高的串口。

2. 对于书写串口通信的代码库，如果往后使用ROS去构建整个工程，建议**使用ROS自带的串口通信库****`Serial`****库**，该库的API文档网址：https://docs\.ros\.org/en/jade/api/serial/html/classserial\_1\_1Serial\.html

去重新封装一个串口通信的实现。基于ROS的节点式通信方式，由于ROS的不同节点间都是并行的，       类似于多线程，所以在ROS上构建串口通信要比写多线程考虑的相对少一些，也更易于使用和维护。

当然即使没有使用ROS也可以尝试使用其他串口通信库，去尝试封装自己需要的串口通信功能。

3. 战队以前的学长提到，使用串口通信的信息交流速度比较慢，结合电子科技大学的交流分享会，

电科大提到他们使用的串口通信使用的虚拟串口，其本质上是can通信，往后队员可以考虑使用其他        连接方式完成上下位机的通信，提高速率和稳定性。
